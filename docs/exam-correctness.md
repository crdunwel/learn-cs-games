# Mock exam correctness argument

The guarantee is scoped to the generator's reviewed question families and stated preconditions. It is **not** based on “500 seeds happened to pass,” and it is not a claim of machine-checked verification of arbitrary C, the compiler, or the browser.

Every call to `generateExam` must pass `assertValidExam` before the paper is returned. The screen and printable paper use that same validated object. The validator does not call the generator's conversion routine or reuse its stored answers as an oracle. An invalid paper throws instead of being returned with an untrusted key.

There are three complementary checks:

1. **Per-instance validation:** independent answer derivations, parameter bounds, queue representation checks, reviewed grading types, question/section weights, and exact reviewed C template contracts.
2. **Compositional proof:** the arguments below cover the complete Cartesian products of allowed parameters. Where a value is merely carried through a data structure, its magnitude does not change the control flow. Those facts avoid pretending that enumerating a handful of seeds covers billions of papers.
3. **Executable evidence:** exhaustive finite parameter/local-state domains and compiled versions of every distinct generated C template, with memory tracking, injected allocation failure, AddressSanitizer, and UndefinedBehaviorSanitizer.

## Reviewed source boundary

`src/engine/examContracts.js` is a separate allow-list of reviewed C skeletons and grading types. Variable fields have named placeholders; all remaining source text must agree exactly, including whitespace inside string literals. `examValidation.js` extracts each parameter from the displayed code or prompt, checks its allowed domain, and matches both the supplied C and model C to their contracts. A changed statement, operator, base case, type, loop bound, string literal, token boundary, or parameter relationship is rejected until the proof and tests are deliberately updated.

This is a source-integrity gate, not a second C compiler. Its validity depends on the reviewed skeletons and the arguments below. Exact contracts intentionally make future content changes require a new audit. Written C remains self-reviewed against a rubric; alternative correct student implementations are never marked wrong by string comparison.

## Reproduce

```
npm test
node scripts/native-exam-validation.mjs
```

The native check requires Clang. It compiles the **actual generated C text** with `-std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined`, including all 63 varying source-template combinations and the static linked-list/queue functions. The harness tracks allocations itself, because LeakSanitizer is unavailable on some macOS configurations; AddressSanitizer and UndefinedBehaviorSanitizer remain enabled. Temporary C files and binaries are removed afterward.

The exhaustive local-domain tests comprise 14,235 cases beyond the seeded reproducibility suite. These are not 14,235 complete random papers presented as a universal proof: they exercise each factored finite domain, while the invariants establish how independent domains compose. Corruption tests alter every objective key and every reviewed C template and require the runtime gate to reject the paper.

## Findings fixed in this audit

- Resize originally multiplied `factor * N` as int before conversion to size_t. A requested allocation could fit size_t while that intermediate multiplication overflowed. The model now converts N to size_t before multiplication; the native harness checks the formerly unsafe large-N boundary.
- Insertion now states that the new node count fits int. Book allocation states size_t bounds. Runtime analysis states independent m/n and n≥2 explicitly.
- Runtime scaling declares its unit so seconds/milliseconds can be normalized safely by the answer parser.

No set of executed examples alone proves arbitrary C correct. The supported guarantee is a deterministic checked generator built from reviewed templates, with mathematical invariants, exhaustive finite domains where applicable, and an independent validation gate for each delivered exam. Future new templates must extend these contracts, arguments, and tests.
